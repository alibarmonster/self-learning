# Node-based / drag-and-drop canvas editors: UX, visuals and data model for a browser-only "Google Cloud service canvas" lab

Research date: 2026-10-17. n8n source code was read from the `master` branch of github.com/n8n-io/n8n on that date (canvas v2 lives in `packages/frontend/editor-ui/src/features/workflows/canvas/`). Abbreviations: NDV = Node Details View, ADC = Google Cloud Application Design Center, PT = Cisco Packet Tracer.

## 1. n8n workflow editor (canvas v2, Vue Flow): palette, nodes, handles, edges, shortcuts, NDV, execution, JSON

### Takeaway
n8n's canvas is a small, consistent set of parts: 96x96 rounded-square nodes on a 16px grid, with the label under the node. Main handles sit left (input) and right (output). Edges are Bezier curves; hovering one shows a toolbar with "+" (Add) and trash (Delete). A node's border colour shows its state: green success, red error, warning, pinned, and an animated running gradient. Status icons sit bottom-right and show item counts. "Tidy up" runs dagre left-to-right. The JSON stores nodes with `position: [x, y]`, and `connections` are keyed by source node **name** → `main` → array per output index → array of `{node, type, index}`. All of this can be copied directly into SVG + Svelte.

### Cited Findings

**Adding nodes / nodes panel**
- An empty workflow shows **"Add first step"**, which opens the nodes panel to search or browse trigger nodes. In an existing workflow the **Add node** connector opens the panel to search all nodes. Triggers show a **bolt icon** in search results. — [n8n docs: Nodes](https://docs.n8n.io/workflows/components/nodes/)
- Nodes panel shortcuts: **N** opens it, **Enter** inserts the selected node, **Escape** closes it. In categories, **Enter** inserts a node or expands a category/subcategory, **ArrowRight** expands/opens a subcategory, **ArrowLeft** collapses/closes it. — [n8n docs: Keyboard shortcuts](https://docs.n8n.io/keyboard-shortcuts/)
- On the canvas, an unconnected main output handle draws a **"+" (CanvasHandlePlus)** at the end of a short line (`v-if="!isConnected && !isReadOnly"`). After run data exists the plus turns `success` type and the line grows to 80px. — [n8n source: CanvasHandleMainOutput.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/handles/render-types/CanvasHandleMainOutput.vue)
- n8n also renders a **placeholder node**: dashed 2px border, light background, a "plus" icon, and the icon turns primary colour on hover. Double-clicking or activating it emits `replace:node` (opens the panel to choose a node). — [n8n source: CanvasNodeDefault.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/CanvasNodeDefault.vue)

**Node shapes, sizes and labels**
- Constants: `GRID_SIZE = 16`. `DEFAULT_NODE_SIZE = [96, 96]` (GRID*6). `CONFIGURATION_NODE_SIZE` = an 80px circle (radius GRID*5/2, used for AI sub-nodes). `CONFIGURABLE_NODE_SIZE = [256, 96]` (wide nodes such as AI Agent). `NODE_X_SPACING = 128`. `HORIZONTAL_NODE_STEP = 96 + 128`. Positions are snapped with `Math.round(value / GRID_SIZE) * GRID_SIZE`. — [n8n source: nodeViewUtils.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/app/utils/nodeViewUtils.ts)
- Node height grows with handle count: `height = 96 + max(0, maxVerticalHandles - 2) * 32`. So an IF or Switch node with 3+ outputs gets taller. — [n8n source: nodeViewUtils.ts `calculateNodeSize`](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/app/utils/nodeViewUtils.ts)
- Regular nodes use `border-radius: var(--radius--lg)`. **Trigger nodes** use `--trigger-node--radius: 36px` on the **left** corners only (`border-radius: 36px lg lg 36px`), which gives the "D-shape". Configuration (AI sub-)nodes are fully round (`border-radius: height/2`). — [n8n source: CanvasNodeDefault.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/CanvasNodeDefault.vue)
- Trigger nodes also get a **bolt-filled** icon badge to their left. Non-read-only triggers show a flask icon button labelled "Execute workflow" (chat triggers show "Open chat"). — [n8n source: CanvasNodeTrigger.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/parts/CanvasNodeTrigger.vue); string `"nodeView.runButtonText.executeWorkflow": "Execute workflow"` — [n8n en.json](https://github.com/n8n-io/n8n/blob/master/packages/frontend/@n8n/i18n/src/locales/en.json)
- The icon is centred in the node. The **label sits outside, below the node** (`.description { top: 100%; position: absolute; min-width: 2 × node width; margin-top: spacing-2xs }`): label is font-size md, medium weight, centred, clamped to 2 lines. An optional subtitle below it uses font-size xs, tint colour, one line with ellipsis. A disabled node shows an extra "(disabled)" label line, and a strike-through line is drawn across nodes with a single input and output. — [n8n source: CanvasNodeDefault.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/CanvasNodeDefault.vue)

**Node visual states (exact CSS)**
- Default border is **1.5px**, black at 10% opacity (light theme) or white at 15% (dark theme). — [n8n source: _canvasNodeStyles.scss](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/_canvasNodeStyles.scss)
- **Selected**: a 6px box-shadow ring in `--canvas--color--selected-transparent`. **Success**: border `--color--success`. **Error**: border `--color--danger`. **Warning** (parameters "dirty" since the last run): border `--color--warning`. **Pinned**: 2px border `--node--border-color--pinned`. **Disabled**: border `--color--foreground` (grey). — [n8n source: _canvasNodeStyles.scss](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/_canvasNodeStyles.scss), [CanvasNodeDefault.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/CanvasNodeDefault.vue)
- **Running**: an `::after` pseudo-element with `inset: -3px` and a **conic-gradient of rgba(255,109,90)** (n8n coral) that rotates via `@property --node--gradient-angle`, `animation: border-rotate 1.5s linear infinite`. **Waiting** uses the same animation at 4.5s. — [n8n source: _canvasNodeStyles.scss](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/_canvasNodeStyles.scss)
- In the source, the reverse order of the state classes sets priority, so later rules win: selected < success < warning < error < pinned < disabled < running < waiting. — [n8n source: CanvasNodeDefault.vue comment "The reverse order defines the priority"](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/CanvasNodeDefault.vue)
- The status icon (bottom-right corner of the node) is a `v-if` chain, first match wins: restricted (`lock`) → community node not installed (`hard-drive-download`) → disabled (`power`) → execution errors (tooltip titled "Issues:" listing the errors) → validation errors (`node-validation-error` icon, or `key-round` with "Setup required" when credentials are missing) → pinned (`node-pin`) → dirty/warning mark → success mark. The success and warning marks show the **run iteration count**. — [n8n source: CanvasNodeStatusIcons.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/nodes/render-types/parts/CanvasNodeStatusIcons.vue); `"node.issues": "Issues"` — [en.json](https://github.com/n8n-io/n8n/blob/master/packages/frontend/@n8n/i18n/src/locales/en.json)
- After a run, an unconnected output handle shows a label `"{count} item | {count} items"` (key `ndv.output.items`). — [CanvasHandleMainOutput.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/handles/render-types/CanvasHandleMainOutput.vue), [en.json](https://github.com/n8n-io/n8n/blob/master/packages/frontend/@n8n/i18n/src/locales/en.json)
- Hovering a node shows: **Execute step**, **Deactivate**, **Delete**, and a context menu (Open node, Rename node, Pin node, Copy node, Duplicate node, Tidy up workflow, Convert node to sub-workflow, Select all, Clear selection, Delete node). — [n8n docs: Nodes](https://docs.n8n.io/workflows/components/nodes/)
- Node settings: Always Output Data, Execute Once, Retry On Fail, On Error (Stop Workflow / Continue / Continue (using error output)), and Notes with "Display note in flow" (shown as a subtitle on the canvas). — [n8n docs: Nodes](https://docs.n8n.io/workflows/components/nodes/)

**Connections / edges**
- Creating a connection: drag from "the grey dot or **Add node** on the right side of the first node" to "the grey rectangle on the left side of the following node". Deleting: hover the connection and select the **Delete** icon. — [n8n docs: Connections](https://docs.n8n.io/workflows/components/connections/)
- Edge rendering: Vue Flow `getBezierPath` for forward edges. When the target sits more than 20px **left** of the source (a backwards edge), n8n draws two `getSmoothStepPath` segments that loop **130px below** the source (`EDGE_PADDING_BOTTOM = 130`, `EDGE_PADDING_X = 40`, `EDGE_BORDER_RADIUS = 16`). Non-main (AI) connections always use the plain bezier. — [n8n source: getEdgeRenderData.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/utils/getEdgeRenderData.ts)
- Edge style: `stroke-width: 2` (multiplied by a zoom-compensation factor), `stroke-linecap: square`, grey by default (oklch lightness, lighter or darker on hover). The stroke is `--color--success` (green) after a successful run and `--color--secondary` when the data is pinned. **Non-main connections are dashed `5,6`.** Main connections get an arrow `marker-end`. Hit area: `interaction-width = 40` (an invisible wide stroke). — [n8n source: CanvasEdge.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdge.vue)
- Hover toolbar: placed at the edge's label position (the bezier midpoint), with `translate(-50%,-50%)`. It holds an outline icon button `plus` (tooltip "Add", aria-label "Add node") and `trash-2` (tooltip "Delete", aria "Delete connection"). Hover-out is delayed (`HOVER_DELAY.LEAVE`) so the pointer can reach the buttons. When not hovered, the same spot shows the edge label (for example the item count). — [n8n source: CanvasEdge.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdge.vue), [CanvasEdgeToolbar.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdgeToolbar.vue)

**Keyboard / pan / zoom (exact keys from docs)**
- Workflow: Ctrl/Cmd+Alt+N new, Ctrl/Cmd+O open, Ctrl/Cmd+S save, Ctrl/Cmd+Z undo, Ctrl/Cmd+Shift+Z redo, **Ctrl/Cmd+Enter execute workflow**. — [n8n docs: Keyboard shortcuts](https://docs.n8n.io/keyboard-shortcuts/)
- Pan: Ctrl/Cmd+left-drag, Ctrl/Cmd+middle-drag, **Space+drag**, middle-drag, two-finger touch. Zoom: **+ or =** in, **- or _** out, **0 reset zoom**, **1 zoom to fit**, **Ctrl/Cmd+wheel**. — [n8n docs: Keyboard shortcuts](https://docs.n8n.io/keyboard-shortcuts/)
- Nodes: double-click opens the NDV. Ctrl/Cmd+A select all, Ctrl/Cmd+V paste, **Shift+S add sticky note**, Alt+G / Shift+Alt+G expand/collapse groups. With a selection: arrow keys move selection to the neighbouring node, Shift+ArrowLeft/Right selects everything left/right, Ctrl/Cmd+C/X copy/cut, Ctrl/Cmd+G / Ctrl/Cmd+Shift+G group/ungroup, **D deactivate, Delete delete, Enter open, F2 rename, P pin data**. In an empty parameter, typing **=** switches to expression mode. **Ctrl/Cmd+K** opens the Command Bar. — [n8n docs: Keyboard shortcuts](https://docs.n8n.io/keyboard-shortcuts/)

**Tidy up (auto-layout)**
- `useCanvasLayout` uses **@dagrejs/dagre** with `rankdir: 'LR'`, `nodesep = edgesep = 96` (GRID*6), `ranksep = 128` (GRID*8), and snaps results to the 16px grid. AI sub-nodes get separate spacing (`AI_X_SPACING = 48`, `AI_Y_SPACING = 128`), and disconnected subgraphs are separated by 128. — [n8n source: useCanvasLayout.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/composables/useCanvasLayout.ts)

**NDV and parameter types**
- Double-clicking a node shows its input and output data in **Schema, Table or JSON** views. Schema shows the structure of the first item only. Execution logs let you review past runs and the data passed through each node. Output data can be edited in the JSON view and saved, which pins it; this is not available for production executions. — [n8n docs: Data](https://docs.n8n.io/data) (via search summary); [mirror of data-editing.md](https://huggingface.co/datasets/Jeice/n8n-docs-v2/blob/main/docs/data/data-editing.md)
- Parameter UI element types (node-definition schema): `string` (`typeOptions.password`, `rows`), `number` (`minValue`, `maxValue`, `numberPrecision`), `boolean`, `dateTime`, `color`, `options` (`options: [{name, value}]`), `multiOptions`, **`collection`** (optional fields behind a button, e.g. `placeholder: 'Add option'`, `default: {}`), **`fixedCollection`** (grouped and repeatable with `typeOptions.multipleValues`, `options: [{name, displayName, values: [...]}]`, e.g. "Add Metadata"), `filter`, `assignmentCollection`, `resourceLocator` (modes: ID / URL / list), `resourceMapper`, `json`, `html`, and **`notice`** (yellow info box). Fields carry `displayName`, `name`, `type`, `default`, `required`, `placeholder`, `hint`. Conditional visibility uses `displayOptions: { show: { resource: [...], operation: [...] } }`. — [n8n docs: Node UI elements](https://docs.n8n.io/integrations/creating-nodes/build/reference/ui-elements/)

**Workflow JSON format (primary source: TypeScript interfaces)**
- `INode { id: string; name: string; typeVersion: number; type: string; position: [number, number]; disabled?; notes?; notesInFlow?; retryOnFail?; maxTries?; alwaysOutputData?; executeOnce?; onError?; parameters: INodeParameters; credentials?; webhookId? }`. — [n8n source: packages/workflow/src/interfaces.ts](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/interfaces.ts)
- `IConnections { [sourceNodeName]: INodeConnections }`, `INodeConnections { [connectionType e.g. "main"]: NodeInputConnections }` (an array indexed by **output index**, each entry an array of targets), `IConnection { node: string /* target node name */; type: NodeConnectionType /* e.g. "main" */; index: number /* target input index */ }`. Example: `"connections": {"IF": {"main": [[{"node":"A","type":"main","index":0}], [{"node":"B","type":"main","index":0}]]}}`, where output 0 = true and output 1 = false. — [n8n source: interfaces.ts](https://github.com/n8n-io/n8n/blob/master/packages/workflow/src/interfaces.ts); format corroborated by third-party docs [Mintlify n8n core concepts](https://mintlify.com/n8n-io/n8n/core-concepts), [n8n-MCP workflows concept](https://www.mintlify.com/czlonkowski/n8n-mcp/concepts/workflows)
- Because connections are keyed by node **name**, a validator has to check that "All connections reference existing nodes", and renaming a node means rewriting its connection keys. — [n8n-MCP workflows concept](https://www.mintlify.com/czlonkowski/n8n-mcp/concepts/workflows)

### Inferences
- **What to copy for the GCP lab:** 96x96 tiles on a 16px grid; label below the tile (so the tile itself holds only the service icon); a D-shaped left edge for "entry point" services (Cloud Scheduler, Pub/Sub push, HTTPS Load Balancer, Eventarc, which work like n8n triggers); the border-colour state machine (idle grey → running animated gradient → success green / error red / warning amber for "config changed since last deploy"); the bottom-right status glyph with a count (e.g. "3 req" or "1 row"); the edge midpoint hover toolbar (+ insert / trash); dashed edges for non-data relationships (IAM/identity, VPC attachment, Secret mounts), which mirrors n8n's dashed non-main edges.
- Keep n8n's **name-keyed connection shape** only for import/export compatibility. Internally, use stable IDs (`edges: [{id, from:{node,port}, to:{node,port}, kind}]`) so renames are free. n8n's own Vue Flow layer also converts to id-based edges.
- The backwards-edge routing (loop under the source with smoothstep corners) is worth copying because learners often place a consumer to the left of its producer. A plain bezier would cut through the source tile.
- Use n8n's parameter-type vocabulary for service config forms: `options` → region/machine type dropdowns, `boolean` → "Allow unauthenticated", `collection` → "Add option" for advanced fields (this is also what ADC's "Show advanced fields" does), `fixedCollection` with `multipleValues` → env vars / labels / firewall rules, `notice` → hints. Use `displayOptions.show` for conditional fields (e.g. show "VPC connector" only when "Egress = private-ranges-only").
- The issue glyph (validation errors listed in a tooltip titled "Issues:") is the right pattern for "missing required config" before deploy. ADC's required fields for Cloud Run (Project ID, Region, Service Name) map directly onto it.

### Gaps
- The current n8n keyboard-shortcuts page lists **N** (not Tab) to open the nodes panel, and it does **not** list **Shift+Alt+T** for Tidy up. "Tidy up workflow" is confirmed only as a context-menu item. Tab and Shift+Alt+T may still work but were not verified.
- I did not fetch the NDV layout component, so the exact column names (INPUT / PARAMETERS / OUTPUT) and the "Logs" panel UI were not verified from source or docs this session. The docs confirm only the Schema/Table/JSON input/output views and execution logs.
- The minimap and sticky-note visuals were not inspected (only Shift+S was confirmed).
- Concrete pixel values of design tokens (`--spacing--5xs` border width for status states, `--color--success` hex) were not resolved. Running uses rgba(255,109,90).
- How validation errors are computed (required parameter missing → issue) was not read from source.

## 2. Cisco Packet Tracer (8.x): palette, cabling and link lights, device config tabs, Simulation mode, Activity Wizard

### Takeaway
PT is effective for learning because it gives three kinds of feedback in the same place. **Physical-layer** feedback comes from link lights (green up, red down, amber blocking, black console). **Config tabs show their CLI equivalent**: changing a GUI field shows the "Equivalent IOS Commands". **Simulation mode** lets you step through the run, with an event list and PDUs whose OSI-layer details you can open. The **Activity Wizard** grades the learner's network against an answer network, showing a percentage and green-check/red-X feedback per item. All four ideas map well onto a GCP lab.

### Cited Findings

**Cables and link lights**
- Cable types: **Console** (PC to router/switch; speed, parity and data bits must match), **Copper Straight-Through** (devices at different OSI layers, e.g. switch to PC, router to hub; 10/100/1000 Mbps), **Copper Cross-Over** (same layer, e.g. PC to PC, hub to hub), **Fiber** (single-mode and multi-mode; 100/1000 Mbps), **Phone** (modem ports only), **Coaxial**, **Serial DCE/DTE** (clocking must be enabled on the DCE side for the line protocol to come up; a clock icon marks the DCE end), **Octal**, **IoE Custom Cable**, **USB**. Each cable type connects only to certain interface types. — [PT help: Connections / Links](https://tutorials.ptnetacad.net/help/default/connectionsLinks.htm)
- Link-light semantics: **bright green triangle** = physical link up (this does not confirm line protocol), **blinking green** = activity, **red down triangle** = physical link down, **round amber** = port blocking because of STP (switches only), **round black** = console cable in the correct port. Some connections have no lights. — [PT help: Connections / Links](https://tutorials.ptnetacad.net/help/default/connectionsLinks.htm)
- Labs say the lights turn green when the correct cable is used, and amber changes to green after about 30 seconds once STP reaches forwarding. — [NetAcad lab 4.2.4.5 Connecting a Wired and Wireless LAN](https://cisco.tu-sofia.bg/wp-content/uploads/courses/CCNA1/course/files/4.2.4.5%20Packet%20Tracer%20-%20Connecting%20a%20Wired%20and%20Wireless%20LAN%20Instructions.pdf); a third-party guide says red "almost always" means the wrong cable — [NetPilot blog](https://www.netpilot.io/blog/connect-wired-and-wireless-lan-packet-tracer)
- The **"Automatically Choose Connection Type"** tool (a lightning-bolt icon) picks the cable for you. Sources disagree on where the icon sits (a gold bolt in the device toolbar vs an orange bolt at the bottom-left). — [NetPilot blog](https://www.netpilot.io/blog/connect-wired-and-wireless-lan-packet-tracer); [NetAcad lab](https://cisco.tu-sofia.bg/wp-content/uploads/courses/CCNA1/course/files/4.2.4.5%20Packet%20Tracer%20-%20Connecting%20a%20Wired%20and%20Wireless%20LAN%20Instructions.pdf)

**Device configuration window**
- Tabs depend on the device. **Physical** (power on/off, insert modules such as a wireless NIC), **Config** (a GUI for basic settings; "as settings are changed in the GUI, the equivalent CLI commands appear in the **Equivalent IOS Commands** window", and one guide notes that Config "does not provide a real world environment"), **CLI** (direct IOS; commands entered from Config also appear here), **Desktop** (end devices: IP Configuration, Command Prompt, Web Browser, wireless config). — [NetAcad 2.1.1.4 Configure End Devices](https://contenthub.netacad.com/legacy/I2PT/1.1/en/course/files/2.1.1.4%20Packet%20Tracer%20-%20Configure%20End%20Devices.pdf) and other course materials found via search ([Module 3 PDF](https://ciscoacademy.cu.edu.ge/wp-content/uploads/masala/qseli/Module3.pdf))

**Simulation mode**
- Switching to Simulation shows the **Simulation Panel**. Switching to Realtime and back restarts the simulation. **Add Simple PDU**: click the tool, then the source device and the destination device. The source queues an ICMP/ARP packet until the simulation runs. — [PT help: Simulation Mode](https://tutorials.ptnetacad.net/help/default/mode_simulation.htm)
- Play controls: **Auto Capture / Play** (press again to pause), **Capture / Forward** (one step), **Back** ("revisit a previous timeframe and view the events that occurred then"), **Reset Simulation** (clears the Event List), **Play Speed Slider**, and an **Event List** toggle. — [PT help: Simulation Mode](https://tutorials.ptnetacad.net/help/default/mode_simulation.htm)
- **Event List columns:** Visible (eye icon), **Time** (seconds since the last restart; advances only when events occur), **Last Device**, **At Device**, **Type** (ICMP, ARP, EIGRP…), **Info** (details "broken up into each layer of the OSI model"). Columns can be reordered by dragging. **Edit Filters** hides protocols ("they are still in the network; you just do not see them"), **Show All** restores them, and **Edit ACL Filters** builds extended-ACL filters. — [PT help: Simulation Mode](https://tutorials.ptnetacad.net/help/default/mode_simulation.htm)
- The simulation resets to 0.000 and clears the event list on reset, power cycle, any network or config change, or a scenario switch. PDU definitions survive and can only be removed from the User Created Packet Window. The PDU information window has an **Outbound PDU Details** tab with headers. — [PT help: Simulation Mode](https://tutorials.ptnetacad.net/help/default/mode_simulation.htm)
- Clicking the coloured box in the event list's last column opens the PDU Information window. Labs ask students why PDUs appear in "so many different colors" but don't give an answer. — [UTM Lab 2 PT for students](https://people.utm.my/murtadha/wp-content/uploads/sites/717/2014/02/Lab-2-Packet-Tracer-for-Students.pdf) (via search summary); [NetAcad 7.3.1.2 TCP/UDP lab](https://cisco.tu-sofia.bg/wp-content/uploads/courses/CCNA1/course/files/7.3.1.2%20Packet%20Tracer%20Simulation%20-%20Exploration%20of%20TCP%20and%20UDP%20Instructions.pdf)

**Activity Wizard / assessment**
- The learner clicks **Check Results** at the bottom of the Activity window and sees an **Overall Feedback** tab. Each assessment item is marked **Correct/Incorrect** against the author's **answer network**. A **green check** on every component means complete, a **white check** means a category is partly complete, and a **red X** means an item is missing or incorrect. The "Completed Feedback" message shows at 100%, otherwise "Incomplete Feedback". — [PT help: Running Activity Files](https://tutorials.ptnetacad.net/help/default/activityWizard_run.htm); [PT help: Assessment Items](https://tutorials.ptnetacad.net/help/default/activityWizard_assessmentItems.htm)
- **Dynamic percentage feedback** re-assesses the user's network against the assessment tree "every few seconds". It can show a score, an item-count percentage, or both. Connectivity tests are not part of the dynamic assessment. Authors can delay forwarding of the answer network so results aren't checked before it has converged. — [PT help: Activity Wizard](https://tutorials.ptnetacad.net/help/default/activityWizard.htm); [PT help: Answer Network](https://tutorials.ptnetacad.net/help/default/activityWizard_answerNetwork.htm) (attribution to these pages comes from the search summary)

### Inferences
- **Copy "Equivalent IOS Commands" as an "Equivalent gcloud command" pane** under each service's config form. Every form change re-renders the `gcloud run deploy … --region=… --allow-unauthenticated` line. This ties the canvas to the repo's existing Cloud Shell simulator and command quiz. Google's console already does the same thing with its **Equivalent code** button (section 3).
- **Copy link lights onto edges:** green = the connection is valid and wired (IAM/env auto-configured), amber = valid but pending (e.g. the target is not deployed yet, or IAM is propagating during a simulated deploy), red = invalid pairing (e.g. Cloud Storage → Cloud SQL "data" edge), black/grey = management-only links (e.g. IAM-only). This is more legible to learners than a modal error.

Show a live percentage plus a tree of green checks, white partial checks and red X marks. Pair it with n8n-style node issue badges.

## 3. Google Cloud canvas tools (ADC, Architecture Diagramming Tool, console "Equivalent code") and comparables (AWS Infrastructure Composer etc.): connections, auto-config, IaC, validation

### Takeaway
ADC is the closest real analogue. Templates are made of **components** (assets, services, workloads) and **connections**. Connecting components automatically writes **env vars and IAM role bindings** into the generated Terraform; for example Cloud Run → Cloud SQL adds `roles/cloudsql.client` + `roles/cloudsql.instanceUser`. Required fields must be filled before deploy, and a draft becomes an application when deployed. ADC went Preview on 2025-03-28 and GA on 2025-12-05. AWS Infrastructure Composer uses the same model: drag port to port; connections provision IAM policies, env vars and events; unsupported pairs get a message; standard (non-enhanced) resources show dotted lines. That **connection → auto-config rule table** is the core of a credible simulated lab.

### Cited Findings

## 4. Implementation notes for a vanilla SVG/HTML node editor in Svelte 5 (no canvas library)

### Takeaway
Everything n8n gets from Vue Flow can be rebuilt with about 600 lines of Svelte. You need: a world `<g transform="translate(px,py) scale(z)">`; pointer events with `setPointerCapture` for node drag, pan, rubber-band selection and connection drag; the React Flow bezier formula (`C` control points offset horizontally by `0.5·dx`, or `curvature·25·√(-dx)` for backwards edges); a 16px snap; a fat invisible stroke for edge hit-testing; dagre-style LR layering for tidy up; and an undo stack of JSON snapshots.

### Cited Findings
- **Bezier edge formula (React Flow / xyflow `getBezierPath`, default `curvature = 0.25`):** `calculateControlOffset(d, c) = d >= 0 ? 0.5*d : c*25*Math.sqrt(-d)`. For a Right-side source handle the control point is `[sx + offset(tx - sx), sy]`, and for a Left-side target handle it is `[tx - offset(tx - sx), ty]`. The path is `M sx,sy C c1x,c1y c2x,c2y tx,ty`. The label/toolbar position is the t=0.5 point: `x = 0.125*sx + 0.375*c1x + 0.375*c2x + 0.125*tx` (same for y). — [xyflow source: bezier-edge.ts](https://github.com/xyflow/xyflow/blob/main/packages/system/src/utils/edges/bezier-edge.ts)
- n8n calls Vue Flow's `getBezierPath` / `getSmoothStepPath`. Backwards main edges use two smoothstep segments (130px drop, 40px offset, 16px corner radius). The edge hit area is `interaction-width = 40`. — [n8n source: getEdgeRenderData.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/utils/getEdgeRenderData.ts), [CanvasEdge.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdge.vue)
- n8n's grid is 16px, with snap `Math.round(v/16)*16`. Default node 96x96. Tidy-up: dagre `rankdir: 'LR'`, `nodesep/edgesep = 96`, `ranksep = 128`. — [nodeViewUtils.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/app/utils/nodeViewUtils.ts), [useCanvasLayout.ts](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/composables/useCanvasLayout.ts)
- n8n keeps strokes and toolbars readable at any zoom by multiplying stroke width and toolbar scale by `--canvas-zoom-compensation-factor`. — [CanvasEdge.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdge.vue), [CanvasEdgeToolbar.vue](https://github.com/n8n-io/n8n/blob/master/packages/frontend/editor-ui/src/features/workflows/canvas/components/elements/edges/CanvasEdgeToolbar.vue)
- Pan/zoom bindings to reproduce: Space+drag, middle-drag, Ctrl+wheel zoom, two-finger touch pan, keys `0` reset, `1` fit, `+`/`-`. Undo is Ctrl+Z and redo Ctrl+Shift+Z. — [n8n docs: Keyboard shortcuts](https://docs.n8n.io/keyboard-shortcuts/)

### Inferences
(Engineering recommendations drawn from the findings above and standard web-platform behaviour. They are not separately sourced in this pass.)

**Data model (Svelte 5 `$state`)**
```ts
type Port = { id: string; side: 'left'|'right'|'bottom'; kind: 'data'|'invoke'|'identity'|'network' };
type SvcNode = { id: string; type: 'cloud_run'|'cloud_sql'|'pubsub_topic'|'gcs_bucket'|'bigquery'|'secret'|'lb_https'|'service_account'|...;
  name: string; position: [number, number]; params: Record<string, unknown>; disabled?: boolean;
  status?: 'idle'|'running'|'success'|'error'|'warning'; issues?: string[]; runCount?: number };
type Edge = { id: string; from: { node: string; port: string }; to: { node: string; port: string }; kind: Port['kind'];
  derived?: { env: Record<string,string>; iam: string[] } }; // filled by the rules table
type Doc = { version: 1; nodes: SvcNode[]; edges: Edge[]; viewport: { x: number; y: number; zoom: number }; stickies?: {...}[] };
```
Export an n8n-compatible view for familiarity: `connections[sourceName].main[outIdx] = [{ node: targetName, type: 'main', index: inIdx }]`.

**Coordinate transform**
- `world = (screen - svgRect.topLeft - pan) / zoom`.
- To zoom around the cursor, keep the world point under the cursor fixed: `newPan = cursor - (cursor - pan) * (newZoom / zoom)`. Clamp zoom to about 0.25–2.
- Zoom to fit: compute the node bounding box, add padding, then `zoom = min(vw/bw, vh/bh)` and centre the box.

**Pointer handling**
- Use a single `pointerdown` on the `<svg>` and dispatch on `event.target.closest('[data-node]|[data-port]|[data-edge]')`. Call `svg.setPointerCapture(e.pointerId)` so drags continue outside the element, and track `pointermove`/`pointerup`/`pointercancel`.
- Modes: `pan` (background + Space or middle button, or background drag), `marquee` (Shift+background drag → rubber band, select nodes whose rects intersect), `dragNodes` (moves all selected nodes, snapping on drop to 16), `connect` (from an output port: draw a temporary bezier to the cursor; on release, hit-test `document.elementFromPoint` or the nearest compatible port within about 20px, the same tolerance as n8n's `HANDLE_SIZE = 20`).
- Use a ~4px movement threshold to tell a click (select/open panel) from a drag. Use `touch-action: none` on the svg. For touch pinch zoom, track two active pointers.

**Palette → canvas**
- Prefer **pointer-based drag** (create a ghost element and drop at `screenToWorld`) over HTML5 drag-and-drop. HTML5 DnD is unreliable for touch input and gives poor control of the drag image.
- Also support **click to add**, as n8n does: the node is placed to the right of the selected node at `+HORIZONTAL_NODE_STEP` (224px) or at the viewport centre, and auto-connected when added from an output "+".
- Provide a keyboard-searchable palette (N or "/" opens it, arrows plus Enter insert, Esc closes), as in n8n's nodes panel.

**Rendering**
- Use one `<path>` per edge, plus a transparent duplicate with `stroke-width: 40` for hit-testing. Use an arrow marker for data edges and `stroke-dasharray: 5 6` for identity/network edges.
- Put the edge toolbar in a `<foreignObject>` or an HTML overlay at the t=0.5 midpoint. Delay the hover-out by about 100–300ms.
- Draw nodes as HTML overlays positioned with the same transform (simpler forms and text), or as SVG `<g>`. Put the label under the tile.
- Use CSS custom properties for state colours. A running border can be a `@property` conic-gradient animation as in n8n, or an SVG `stroke-dashoffset` animation. Honour `prefers-reduced-motion`.

**Simulation ("Execute / Deploy")**
- Do a topological sort from entry nodes, then use an async generator that yields events `{t, from, at, type, info}`.
- Animate a token along each edge with `path.getPointAtLength(len * progress)`.
- Support step / play / back by keeping a list of event snapshots, and a PT-style Event List table with filters.
- Errors (missing required param, invalid edge, missing IAM role) put a node into the error state and add an "Issues" tooltip.

**Undo/redo**
- Push `structuredClone(doc)` (or a JSON string) to `past[]` on each committed action (drop, connect, delete, param blur, end of node drag; not on every pointermove), and clear `future[]`. Cap the stack at about 100 entries.
- Bind Ctrl/Cmd+Z and Ctrl/Cmd+Shift+Z (also Ctrl+Y). Ignore these when focus is in an input.

**Persistence**
- Debounce `localStorage.setItem('gcp-canvas:v1', JSON.stringify(doc))` and wrap it in try/catch.
- Validate on load: drop edges that point to missing nodes, which is the same check n8n validators run.
- Provide Export/Import of a JSON file and a versioned schema field.

**Keyboard accessibility**
- Make nodes focusable (`tabindex="0"`, `role="group"`, `aria-label="Cloud Run service api, 2 issues"`).
- Arrow keys move selection to the neighbouring node (as in n8n). Shift+Arrow or Alt+Arrow nudges the node 16px. Enter opens the config panel. F2 renames. Delete removes. D disables. Ctrl+A / C / V. 0 / 1 / + / - for zoom.
- Offer a keyboard "connect" flow (select the source, press C, cycle valid targets with arrows, Enter). Announce validation results through an `aria-live` region.

**Tidy up without dagre**
- Use longest-path layering from sources (rank = max(rank(pred)) + 1), x = rank × 224 (96 + 128), and order within a rank by the average y of predecessors (one barycenter pass). Then y = index × (96 + 96) and snap to 16. This approximates n8n's dagre LR configuration. Optionally vendor `@dagrejs/dagre`, since it is a small, MIT-licensed, framework-free library.
